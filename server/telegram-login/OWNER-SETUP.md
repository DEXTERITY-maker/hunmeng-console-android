# Настройка Login для Hunmeng Console

Владелец выбрал **@hunmeng_official_bot** 4 октября 2026 года. Публичная страница бота доступна; это не подтверждает настройку Login или право управления. На действующем backend `/api/account/login/config` возвращает `configured: false`: Client ID и Client Secret отсутствуют, серверный ключ шифрования уже задан как secret.

## BotFather

Открыть мини-приложение [@BotFather](https://t.me/botfather), выбрать `@hunmeng_official_bot`, затем **Bot Settings → Login Widget**. [Официальная инструкция](https://core.telegram.org/bots/telegram-login).

Для Android зарегистрировать приложение с фактическими данными подписанного APK:

| Поле | Значение |
| --- | --- |
| Приложение | Hunmeng Console |
| Package Name | `chat.hunmeng.console` |
| SHA-256 сертификата | `d052c3aa276facde5f2bab22713ae76e31fc1b3a1262bc7e6b284df5522a554a` |
| Алгоритм ID token | RS256 (стандартный) |

Тот же отпечаток с разделителями, если форма требует такой формат:

```text
D0:52:C3:AA:27:6F:AC:DE:5F:2B:AB:22:71:3A:E7:6E:31:FC:1B:3A:12:62:BC:7E:6B:28:4D:F5:52:2A:55:4A
```

После регистрации взять **Client ID**, выданный BotFather. Username бота не подставляется вместо числового Client ID. Номер не вычисляется из неподтверждённых данных. App Link имеет вид `https://app<CLIENT_ID>-login.tg.dev/tglogin`; согласно [документации Android](https://github.com/TelegramMessenger/telegram-login-android#2-setup-in-botfather), базовый домен генерируется автоматически при регистрации приложения. Это не свой домен, который нужно приобретать или настраивать через DNS.

При настройке веб-входа добавить соответствующие фактические Allowed URLs. Origin существующего сайта: `https://telegram-bot-console.hunmeng.chatgpt.site`. Android и browser backend имеют отдельные маршруты/таблицы; успешный вход одной платформы не считается проверкой другой.

## Передача конфигурации

- **Client ID** — публичный; его можно сообщить в переписке. После получения он используется в runtime и параметре сборки `telegram_login_client_id`.
- **Client Secret** — только из Login Widget, через защищённые настройки сервера. Значение не включается в APK, исходники, GitHub, отчёты или переписку.
- На телефоне возможен ввод через буфер обмена: владелец копирует именно Client Secret и явно сообщает, что секрет скопирован. После этого можно попробовать `termux-clipboard-get` с timeout 20, передав значение только в памяти напрямую в Sites runtime с `is_secret: true`. Значение и полный результат команды не выводить. Доступ к clipboard заранее не считается подтверждённым; при ошибке/таймауте остановить этот способ, не заменять его публикацией секрета в чате.
- Секреты и существующий серверный ключ сохраняются в runtime. После изменения конфигурации применить её через deployment уже сохранённой Site-версии, проверить endpoint без вывода секретов.

Проверка `/config: true` означает наличие необходимых настроек. Правильность секрета и фактический вход подтверждаются отдельным настоящим Login flow на устройстве.

## Дальнейшая проверка

Собрать APK с настоящим Client ID, подписать постоянным ключом, проверить APK/сертификат/host, затем вход/отмену/возврат/восстановление. TDLib подключается отдельно по согласию; API ID/hash вводятся в приложении. Готовность профиля не доказывает загрузку списка ботов.
