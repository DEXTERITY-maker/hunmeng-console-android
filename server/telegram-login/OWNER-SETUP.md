# Настройка Login для Hunmeng Console

Владелец выбрал **@hunmeng_official_bot** 4 октября 2026 года и предоставил публичный OIDC Client ID **8883240190**. Client Secret сохранён только как защищённая runtime-переменная сервера. Применена версия backend 10 / runtime revision 4: config/begin/cancel каждый HTTP 200, правильный redirect, PKCE S256 и минимальные scopes подтверждены. Правильность секрета ещё не подтверждена настоящим обменом кода.

На скриншоте владельца BotFather показывает Android package `chat.hunmeng.console`, постоянный сертификат и отдельный **App URL `https://app1853479971-login.tg.dev`**. Этот идентификатор не равен OIDC Client ID. Assetlinks по фактическому домену вернул **HTTP 200** и подтвердил полный сертификат и `delegate_permission/common.handle_all_urls`.

Предыдущие 404 относились к ошибочно вычисленному `app8883240190-login.tg.dev`; вывод о неподтверждённой регистрации был неверным. Регистрация владельца подтверждена. Сервер, APK и инструмент подписи теперь принимают App URL отдельно от Client ID; fallback путём вычисления из Client ID удалён.

## BotFather

Открыть мини-приложение [@BotFather](https://t.me/botfather), выбрать `@hunmeng_official_bot`, затем **Bot Settings → Login Widget**. [Официальная инструкция](https://core.telegram.org/bots/telegram-login).

Для Android зарегистрировать приложение с фактическими данными подписанного APK:

| Поле | Значение |
| --- | --- |
| Приложение | Hunmeng Console |
| OIDC Client ID | `8883240190` |
| Native App URL | `https://app1853479971-login.tg.dev` |
| Redirect URI | `https://app1853479971-login.tg.dev/tglogin` |
| Package Name | `chat.hunmeng.console` |
| SHA-256 сертификата | `d052c3aa276facde5f2bab22713ae76e31fc1b3a1262bc7e6b284df5522a554a` |
| Алгоритм ID token | RS256 (стандартный) |

Тот же отпечаток с разделителями, если форма требует такой формат:

```text
D0:52:C3:AA:27:6F:AC:DE:5F:2B:AB:22:71:3A:E7:6E:31:FC:1B:3A:12:62:BC:7E:6B:28:4D:F5:52:2A:55:4A
```

Полученный от владельца **Client ID `8883240190`** используется в runtime и параметре сборки. App Link берётся из отдельного поля **App URL**: `https://app1853479971-login.tg.dev/tglogin`; согласно [документации Android](https://github.com/TelegramMessenger/telegram-login-android#2-setup-in-botfather), базовый домен генерируется автоматически при регистрации приложения. Покупка домена и настройка DNS не требуются. Username бота не подставляется вместо числового Client ID.

При настройке веб-входа добавить соответствующие фактические Allowed URLs. Origin существующего сайта: `https://telegram-bot-console.hunmeng.chatgpt.site`. Android и browser backend имеют отдельные маршруты/таблицы; успешный вход одной платформы не считается проверкой другой.

## Передача конфигурации

- **Client ID** — публичный; текущий `8883240190` уже используется в runtime и параметре сборки `telegram_login_client_id`. Сопоставление выбранного Client ID с native App URL ID явно хранится в `gradle.properties`. При запуске CI без Client ID остаётся тестовое значение `0`.
- **Redirect URI** — публичный `https://app1853479971-login.tg.dev/tglogin`, в runtime `TELEGRAM_LOGIN_REDIRECT_URI`. Не вычислять из Client ID.
- **Client Secret** — только из Login Widget, через защищённые настройки сервера. Значение не включается в APK, исходники, GitHub, отчёты или переписку.
- На телефоне возможен ввод через буфер обмена: владелец копирует именно Client Secret и явно сообщает, что секрет скопирован. После этого можно попробовать `termux-clipboard-get` с timeout 20, передав значение только в памяти напрямую в Sites runtime с `is_secret: true`. Значение и полный результат команды не выводить. Доступ к clipboard заранее не считается подтверждённым; при ошибке/таймауте остановить этот способ, не заменять его публикацией секрета в чате.
- Секреты и существующий серверный ключ сохраняются в runtime. После изменения конфигурации применить её через deployment уже сохранённой Site-версии, проверить endpoint без вывода секретов.

Проверка `/config: true` означает наличие необходимых настроек. Правильность секрета и фактический вход подтверждаются отдельным настоящим Login flow на устройстве.
