## Работа с ботом

1. Установите APK и откройте Hunmeng Console.
2. Введите токен, полученный у официального `@BotFather`, в поле приложения. Не записывайте его в исходники или CI.
3. Нажмите «Подключить». Приложение проверит бота и синхронизирует команды.
4. Если у бота webhook, приложение объяснит конфликт и предложит удалить его после отдельного подтверждения.
5. Остановите веб-консоль или другую polling-сессию для того же бота, затем нажмите «Запустить».
6. Для ручной отправки введите ID или @username, текст, посмотрите полный предпросмотр и подтвердите отправку.

Бот не может первым начать личный диалог: получатель должен сначала написать боту. Для канала нужны соответствующие права. В случае неизвестной доставки сначала проверьте чат, затем решите, отправлять ли сохранённый черновик снова.

## Расположение проекта

Полный проект находится в `/storage/emulated/0/Hunmeng Console` и доступен файловому менеджеру Android. Старый путь `~/hunmeng-console-android` ведёт в эту папку через символическую ссылку.

В общей памяти Android используйте `sh gradlew` вместо прямого запуска `./gradlew`. Основной путь сборки APK — GitHub Actions.

Android показывает общего владельца файлов; Git требует явного указания доверенной папки для команды:

```sh
git -c safe.directory="/storage/emulated/0/Hunmeng Console" status
```

Локально установлен `core.fileMode=false`, поскольку общая память не сохраняет обычные Unix-права. Права исполняемых файлов в Git-истории сохранены для сборки в CI. Подробности переноса: [TRANSFER.md](TRANSFER.md).

## Сборка через GitHub Actions

Репозиторий: https://github.com/DEXTERITY-maker/hunmeng-console-android (публичный; доступен без входа в GitHub).

1. Откройте вкладку **Actions → Build Android APK → Run workflow**.
2. После успешной сборки откройте её страницу.
3. Скачайте артефакт **hunmeng-console-debug-apk**, распакуйте ZIP.
4. APK находится внутри как `app-debug.apk`. Отчёты тестов и lint доступны в **verification-reports**.

Workflow на Ubuntu x64 устанавливает JDK 17, Android API 36 и Build Tools 35.0.0, проверяет Gradle Wrapper, выполняет `./gradlew testDebugUnitTest lintDebug assembleDebug`. Реальный токен не нужен; сетевые сценарии проверяются локальным mock-сервером. Actions ограничен правами чтения репозитория; внешние actions зафиксированы по commit SHA.

### Termux ARM64

Исходники можно редактировать и хранить в Termux. Если SDK установлен, укажите его в игнорируемом `local.properties`:

```sh
printf 'sdk.dir=%s\n' "$HOME/android-sdk" > local.properties
./gradlew --version
```

На этом телефоне Java 21 и wrapper запускаются, но SDK содержит только платформу API 36. Build Tools 35.0.0 и лицензии отсутствуют. Официальные Linux native Build Tools предназначены для x64 и не устанавливаются для выполнения на ARM. Установленный `adb` запускается командой `env -u LD_LIBRARY_PATH -u LD_PRELOAD adb devices -l`; обычный запуск в среде Codex конфликтует с его native-библиотекой. Последняя успешная проверка вернула пустой список устройств. Основной воспроизводимый путь — Actions; системные каталоги не заменяются.

## Установка

Перенесите APK в «Загрузки» и откройте через файловый менеджер Android. При запросе разрешите установку из этого источника. Подтверждение установщика выполняет владелец телефона. Публичный v0.0.4beta имеет debug-подпись. Новый локальный кандидат из раздела разработки — non-debug APK с постоянной release-подписью; его установка и настоящий вход ещё требуют подтверждения.

Debug-ключ создаётся GitHub runner и может отличаться между сборками. Если Android отказывается обновлять приложение из-за подписи, для стабильных обновлений потребуется отдельно настроенный ключ подписи. Не удаляйте установленное приложение автоматически.

## Данные и ограничения

- Токен хранится только в памяти процесса: без файлов, SavedStateHandle, rememberSaveable, логов, резервных копий и секретов CI. При отключении ссылка на токен очищается; после уничтожения процесса ввод нужен снова.
- Приветствие, язык и эхо сохраняются в SharedPreferences. Облачное резервное копирование и перенос данных между устройствами отключены явными правилами Android.
- Только HTTPS к `api.telegram.org`, обычная TLS-проверка, перенаправления и автоматический повтор отправки отключены.
- В MVP polling работает на переднем плане. Уход в фон останавливает цикл; при возвращении запуск предлагается вручную. Поворот экрана сохраняет ViewModel и не создаёт второй цикл.
- Журнал, токен и черновик не переживают уничтожение процесса. Чувствительные фрагменты не выводятся в журнал.
- Приложение не является универсальным Telegram-клиентом и не получает старую историю сообщений через Bot API.
- Реальное подключение и визуальную проверку на телефоне владелец выполняет в установленном приложении; сборка и mock-тесты не подменяют эту проверку.
